## Design specificity: split, and the split is the finding

**Material 8/10, model 3/10.** A tier drawn as a *gap between two runs* rather
than a coloured band reasons from CONTEXT.md's own definition ("a tier is a
break") to a rendering and invents nothing. The header sentence is one no
generic product writes.

The model is a bulk-import admin screen with the nouns changed. Strip the words
off `/leagues/[id]/sheet` and you have `/players/import` — the code comments say
so out loud. But a roster CSV is a commissioner doing an ingest once a summer,
and a cheat sheet is a friend on a sofa who has never written one and has no
list to paste. **There is no path from the pool into the sheet.** No add, no
remove, no move.

## The detector, quantified rather than quoted

Both runs clean, exit 0, `[]`. Coverage computed rather than assumed:
**22 of 59 rules can execute** on `.tsx`; 37 cannot, including every
accessibility rule. `htmlparser2`, `css-select`, `css-tree`, `domutils`,
`puppeteer` all `MODULE_NOT_FOUND`. A **positive control** (poisoned `.tsx` with
gradient text and bounce easing) produced 2 findings, so the scanner does read
this file type and does fire. Clean means "no purple gradients".

The in-page overlay found three real rules: `all-caps-body` x20 (the `CardName`
conceit — deliberate, but never measured before, and 60 characters of uppercase
in a 159px column is a decision worth re-taking), `text-overflow` x18 (mostly
intended truncation plus one real 3.2 radar clip), `line-length` x2 (**real** —
the sheet form's two explanatory paragraphs have no measure cap and run 81 and
62 ch/line at desktop while the `h1` block above has `max-w-xl`).
`gray-on-color` x1 is a false positive; that pair measures 5.26:1.

## Priority issues

### [P0] The confirm step breaks the page at 390px and hides what it is confirming

`STATUS_NOTE.unmatched` is a 65-character sentence carrying `shrink-0` inside a
`flex-nowrap` row. Measured at a true 390x844: `scrollWidth` **551 vs 390** —
161px of overflow, *clipped not scrollable*. In the same row the name span
measures **0px**, so the line you are told to fix is invisible. Separately,
`was "..."` is guarded by `typed !== player.name`, but the pool stores
"Surname, Firstname" and nobody types that, so it fires on essentially every row
and truncates the *matched* name to print the typed one.

Fix: let the note wrap (drop `shrink-0`, or move it under the name below `sm`);
change the `was` guard to a token-subset test. Command: `/impeccable adapt`.

### [P0] "Read the list" dies after the first save, and eats your typing

`const result = applied.plan ? applied : preview` pins the surface to the last
*applied* plan forever. Reproduced live: saved two players, typed three new
ones, pressed Read the list — the textarea came back with the old text and the
old plan still rendered. React 19's post-action reset restores
`defaultValue={result.csv}`, which is stale. Only a reload recovers.
AGENTS.md warns about this React 19 behaviour by name.

**Inherited: `/players/import` has the identical line** (`applied.preview ?
applied : preview`), shipped in 2.1b. Two surfaces, one bug.

Fix: control the textarea (`value`/`onChange`); clear `applied` on a new
preview. Command: `/impeccable harden`.

### [P0] Saving is silent, invisible, and survives its own undoing

Measured: **zero live regions** on the surface. After a real apply,
`sheet-saved`'s bounding top is **-133px** — above the viewport, nothing scrolls
to it; `document.activeElement` is `BODY`. `clearCheatSheet` writes to a
different `useActionState`, so `applied.saved` persists: after deleting your
sheet the page reads "SAVED — 4 ranked · 2 tier breaks. Autodraft uses this from
now on" in marker red, 60px under an empty ranking. The block uses `slot-live`,
which DESIGN.md reserves for one thing only.

Fix: `slot-filled` not `slot-live`; `role="status"`; clear `applied` on a
successful delete; give delete its own confirmation sentence.
Command: `/impeccable harden`.

### [P1] The pinned block restates the first three pool rows, in the material that means "gone"

Confirmed at the id level: the three `pin-*` buttons and the first three
`pick-*` buttons carry the same three player ids at both viewports — 6 of 11
Pick buttons on screen are for 3 players. `Slot`'s default state is `filled`,
and the pool's own documented convention is that available players are dashed
`waiting` and **drafted players are solid `filled`** — so the three players you
most want are drawn in the material meaning somebody already has them. The block
is not a `Bank` (a bare `<p>` over an unnamed `<ul>` — the radar critique's fixed
finding #10) and its heading is `ink-faint`, the faintest on a page where
"THE RADAR" and "THE BOARD" are `ink-soft`. Pinned rows measure **69px** against
the pool's **61px**, so the two stacks do not share a rhythm.

Fix: drop the pinned block when no query and no filters are active — the pool
below already *is* it — or exclude pinned players from the list. Move `edit it`
onto the pool's `Bank` aside so the door survives.
Command: `/impeccable distill`.

### [P1] Delete is one tap, irreversible, and the sheet cannot be read back out

No confirm, no undo, and no way to obtain your ranking as text: the resting page
renders rows and the textarea loads empty. A 60-line sheet is an hour of
somebody's evening and the only thing between them and an arbitrary autodraft.
Compare `deleteLeague`, which makes you type the league's name.

Fix: (a) arm-then-commit, in the material the pool already uses; (b) **render the
current sheet back into the textarea as `rank,tier,name` on load** — that turns
the paste box into an edit box, gives whole-replace a round trip, and is most of
what 3.4b owes without any drag-and-drop. Command: `/impeccable harden`.

## Persona red flags

**A friend on a couch, 1:43 on the clock.** Between the clock band and the first
pickable player: three pinned rows, a search box, a keyboard hint about arrow
keys they will never press, three position toggles, a five-toggle "Show" row
wrapping to **three lines** on a Pixel 7, and two selects — then the same three
players again. The `#rank` marks sit after the position patch, so `#1`…`#8` land
at eight different x-positions and cannot be scanned down a column: the radar
critique's fixed finding #4, re-broken 20px away.

**The first-timer writing a sheet the night before.** No route from `/players`
into the box, no "add from the pool", no suggestion of how many to rank — and
nothing anywhere shows the sheet's composition against 5G/5F/3C. You can rank
fourteen forwards, read "14 of 323 ranked", and never learn your sheet cannot
fill a roster. The radar exists for exactly this question about rosters.

**iPhone VoiceOver.** Save: silent. Delete: silent. Choosing a candidate in the
ambiguity select: silent, and nothing visible changes. The three tier runs are
three unnamed sibling lists — "list, 4 items" three times — where the tier is the
entire point of the structure; "Tier 1" is a `<p>` outside the `<ul>` with no
`aria-labelledby`. `Slots` accepts no label prop, which is the root cause and a
shared-component fix.

## Minor observations

- The lobby link introduces a sixth type size (`text-lg` at display tracking) —
  the exact mistake the pool critique fixed as its finding #10. Should be `CardName`.
- The ambiguity row is struck as `slot-correction`, this system's declared word
  for an *error*. An ambiguous name is a question; the row's own note says "Which one?".
- The plan's proposed ranks are wrong when an earlier line is ambiguous
  (`resolved.indexOf(row) + 1` counts only resolved rows), and it is O(n²).
- Tier breaks are invisible in the plan. `SheetPlan.tiers` is computed and never shown.
- `orderBySheet` puts drafted players at the top when "hide drafted" is off —
  sheet rank beats availability.
- The textarea is undocumented material: 8 rows wearing `inputStyles`, with a
  native resize grabber — the chrome `appearance-none` exists to refuse.
- A partial rank column is silently ignored. Good rule, no `problems` entry.
- `MAX_CANDIDATES` is 4 but the select offers 5 options — one past its own
  comment, "past four it is not a choice".

## Questions

1. If the pool at rest is already the sheet in the sheet's own order, what is the
   pinned block for? Its only unique content is the `edit it` link and the
   legality filter — and the legality filter is what makes it vanish exactly when
   a member needs the door most.
2. Why can a member read their sheet but not write it? Every other list in this
   app is built by acting on the thing itself.
3. What does the marker mean now? Once "saved" is marker red, is the
   on-the-clock band still the loudest thing on a phone on draft night?
4. A sheet with no centers is a broken sheet, and nothing in this slice can say
   so. Does the sheet page want a radar of its own?
5. Should "this replaces the sheet you have now, whole" be a diff? The plan
   compares your paste against the *pool*, never against *your existing sheet* —
   three added, one dropped, two moved. All the data is already on the server.
