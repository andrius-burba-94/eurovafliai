# ADR-0012: AI commentary over a computed fact sheet

Date: 2026-10-09
Status: accepted; groundwork (7.0) built, nothing user-facing yet

## Context

Phase 7 promised Gemini-written commentary under one hard rule: nothing
latency- or fairness-critical depends on an LLM. Its menu was written for
draft night, which is over. What the league wants now is the season told
back to it: what happened in a round, who should be picked up, what a deal
was worth. Three things make that risky. A model asked to read standings
does arithmetic and gets it wrong. Free-form prose cannot be checked. And a
league's team names, its members' names and their notes are friends'
personal data that a hosted model has no need for.

## Decision

- **The worker computes; the model narrates.** Tested code builds a *fact
  sheet* for each write-up: every number pre-formatted with the repo's own
  formatters, every judgement ("overperformer", "captain flop", "passed @T2")
  a label with a named threshold. The model only turns the sheet into prose.
- **Tokens, not names.** Teams reach the model as `@T1…` (in sorted
  member-id order) and players as `#P1…`. No league, team or user name, no
  note, no publisher headline, no internal id is ever sent; clubs are their
  public codes. Names are put back when somebody reads the write-up, so a
  team rename updates every old one.
- **A guard decides what is shown.** A write-up is refused if it names a
  token the sheet did not issue, cites a number the sheet does not contain,
  spells out a name, or carries markdown or links. One retry with the faults
  listed; a second refusal means nothing is shown. The guard checks
  citations, not the fairness of words like "carried"; the labels are what
  keep those honest.
- **Written once, read the same.** Write-ups are generated by the worker
  (from 7.1) and stored in `ai_writeups`, keyed (league, season, round, kind,
  member) with an input hash over the facts, voice, prompt version and model.
  Pages never call the model. Private advice is generated for every member at
  the same moment and is readable only by its member.
- **Stateless calls, one client.** The Interactions API with `store: false`,
  one framework-free client, the model in `GEMINI_MODEL`
  (default `gemini-3.8-flash`). See `docs/research/gemini-api.md`.

## Consequences

No page gets slower and none depends on Google being up: without a key, or
after a refusal, every surface renders as it does today. Write-ups cost a
few thousand input tokens each and are written once per round, not per
reader. Data minimisation holds on any tier; on the free tier, Google's terms
apply the paid-service data terms to users in the EEA anyway. The price is
that every new kind of write-up needs its fact sheet built and tested first,
which is the point: a feature cannot ship a claim its code did not compute.
A stat correction changes a sheet's hash and so its write-up; when that may
rewrite prose people have already read is 7.1's call.

## Alternatives

- **Let the model read raw tables and compute.** Fewer lines of code, and
  wrong numbers in front of friends who check them.
- **Generate on page load.** Fresh, but slow, paid per reader, and two people
  could read two different stories about one round.
- **Send names and rely on the free tier's terms.** Simpler rendering, but it
  sends friends' names somewhere for no gain and leaves the guard unable to
  tell an invented player from a real one.
