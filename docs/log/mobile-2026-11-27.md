# Mobile app, M1: the shared core and API v1

The first slice of the phone app (blueprint D29). The plan it follows, with
every decision and what was checked against documentation, is
[../mobile/plan-step-0.md](../mobile/plan-step-0.md).

## Why the modules moved rather than being copied

The app has to dim an illegal pick, draw the board and the radar, print
tenths and build the same nav. Each of those has exactly one implementation
here, and a copy would be a second one that drifts. So the files moved, with
git history, into `packages/core`, and the web's imports were rewritten
mechanically: 122 files, no behaviour change, the whole suite green on the
first run after the move.

`navLeagueFrom` did not move. It reads `LeagueWithMembers`, which is built on
PocketBase's `RecordModel`, and the package must not know PocketBase exists.
It lives in `src/lib/nav/league.ts`; the app gets the same `NavLeague` shape
from the API.

The tenths formatters left `scoring.ts` and the box-score arithmetic stayed:
the phone prints numbers, it never computes them.

## Why the session takes a bearer token rather than a second function

The prompt asked for `requireSession` to accept either source. Doing it in
`getSession` turned out to be the larger win: about twenty read functions ask
`getSession()` for the token themselves, and every one of them now serves a
Route Handler unchanged, because `headers()` works there exactly as
`cookies()` does. The cookie wins when both arrive, so nothing a browser
does changes.

## The proxy's new branch

An `/api/v1` request used to be redirected to `/login` like any cookieless
page, which is an HTML answer to a JSON client. The proxy now answers it
with 401 JSON when no credential is presented, and remains optimistic in the
same way as before: presence here, worth in the handler. `meta` is public
so that a build too old to be served can still learn that.

## Proof that Metro reads the package

The plan's riskiest unverified claim was that Metro could bundle TypeScript
source from a `file:`-linked package outside the app. It was tested on a
throwaway Expo SDK 58 app laid out as `apps/mobile` will be, with **no
`node_modules` above it** so that nothing could resolve by accident: both
the iOS and the Android bundle built, importing the engine, the tenths
formatter, `navFor` and a zod schema. One finding for slice 2:
`resolver.disableHierarchicalLookup` breaks Expo's own nested dependencies
(`expo-asset`), so the config is `watchFolders` plus `nodeModulesPaths` and
nothing more. What this did not prove is EAS's upload and install, which
needs the Expo account and is the first thing slice 2 does.

## design.json

The Impeccable sidecar still described the arena system (cyan accent, one
ground), a month after ADR-0011. It was regenerated from `globals.css` with
both grounds. The phone's tokens will be generated from `globals.css`
directly, which DESIGN.md names as the source of truth.
