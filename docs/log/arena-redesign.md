# Arena redesign, 28 September 2026

The approved Visualize concept became the basis for ADR-0009. The user asked to keep the sidebar, give Drafts its own section, keep the League destinations distinct, remove the nonexistent E2025 fantasy season, make the court less stretched, and prevent player labels from colliding. The implementation keeps all five official G/F/C formations and historical player statistics.

The court uses a bounded 1.18 aspect ratio. Center, forward and guard rows are laid out separately. The first browser pass exposed a formation control that only swapped already-filled places and did nothing on an empty roster; formation selection now constructs a complete proposed arrangement while retaining compatible starters. A desktop and phone screenshot pass also showed the sticky save area covering too much of the court, so the secondary actions moved into the court panel and the record bar became compact.

The pool was reordered around player lookup rather than ingest metadata. Standings now expose a leader, most recent round standout and rank movement from the selected phases. Recap and commissioner trade entry use wide layouts. All are built on the current permission gates and stored data. The full desktop and phone capture pass caught a missing display utility on standings sparklines that had inflated every row; a browser size assertion now protects the compact grid. It also exposed an empty trade sentence and a fake matchday tie rank before any scores existed. The trade button now waits for a complete selection, and Matchday names the pending state.

A keyboard pass found that the comparison dialog closed as soon as React's development effect cleanup ran. Opening it only when needed, and letting the DOM close it on unmount, keeps Enter and Escape working in both viewport projects. The same flow checks missing game and fixture data in the drawer.

The official completed-game Boxscore response established field names but did not establish behavior during a game. The live collection and worker pass are isolated from final scoring. `LIVE_FETCH=off` remains the release gate until a real in-game response changes. The page labels provisional, stale and unavailable states; final standings continue to come from the existing finished-game pipeline.

Verification: 1,402 unit tests across 90 files, lint, dead-code lint, typecheck, production build, PocketBase rules and index verification, 53 passing relevant browser flows (one existing desktop-only skip), targeted reruns for the corrected standings, trade and comparison interactions, and full local desktop/phone captures. Browser runs use reduced motion; color token tests cover contrast, and the comparison test covers keyboard activation. Actual in-game feed behavior is the one open verification.
